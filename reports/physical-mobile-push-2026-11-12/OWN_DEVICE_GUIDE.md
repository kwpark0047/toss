# 휴대폰만으로 검증 — 주문 30초 후 자동 준비 완료

> 커밋된 링크·QR은 당시 실행 증거이며 이미 만료될 수 있습니다. 현재 시험은 `node scripts/mobile-push-lab.cjs --isolated-test-only`가 출력하는 새 링크를 사용하세요. 개발자 준비 절차: `scripts/MOBILE_PUSH_LAB.md`.

보유하거나 빌린 Android 휴대폰과 iPhone을 사용한다. BrowserStack·원격 실기기 구독, USB 연결, 별도 앱스토어 앱 설치는 필요 없다. 휴대폰과 테스트 서버 PC가 인터넷에 연결되어 있어야 한다. 두 기기가 같은 Wi-Fi를 사용할 필요는 없다.

격리된 테스트 매장과 합성 점주 계정만 사용한다. 휴대폰에서 로그인하거나 이름·전화번호·주소·카드번호를 입력하지 않는다. 메뉴는 QA 테스트 메뉴 1개, 표시 금액 10,000원이며 **현금 미결제 주문**만 허용한다. 이 금액은 청구되지 않는다. 카드/토스 승인 경로는 차단되어 있다. 이번 시험은 실제 결제 승인 검증이 아니다.

운영 주문 링크를 사용하지 않는다. 완료 화면과 주문 진행 카드는 테스트 도메인에서만 확인한다. 주문 접수 30초 후 테스트 서버가 자동으로 준비 완료로 변경한다. PC 명령과 점주 로그인은 필요 없다. 화면의 남은 시간을 확인하고 30초 안에 알림 동의와 페이지 종료를 마친다.

## 1. Android 준비

1. Chrome 일반 모드로 테스트 시작 링크를 연다. 카카오톡·네이버 등의 앱 내 브라우저와 시크릿 모드는 사용하지 않는다.
2. 기기 환경 확인을 열어 화면을 저장한다. `secureContext: true`, `serviceWorker: true`, `pushManager: true`를 확인한다. 알림 권한은 동의 전에는 default여도 된다.
3. 테스트 시작 화면으로 돌아간다. Android는 이번 Chrome 탭 종료 시험에 홈 화면 설치가 필수는 아니다.

Chrome의 시크릿 모드에서는 알림이 표시되지 않는다. 알림 권한을 이전에 거부했다면 해당 **테스트 사이트**의 권한을 직접 확인한다. [Google 공식 안내](https://support.google.com/chrome/answer/3220216?hl=ko&co=GENIE.Platform%3DAndroid)

## 2. iPhone 준비

1. iOS 16.4 이상 iPhone에서 **Safari**로 테스트 시작 링크를 연다.
2. Safari 공유 → **홈 화면에 추가** → 추가를 누른다. 메뉴에서 항목이 바로 보이지 않으면 공유 목록을 아래로 스크롤한다.
3. 홈 화면의 **푸시 QA** 아이콘을 열고 그 앱 안에서 기기 환경 확인을 연다. `standalone: true`, `secureContext: true`, `pushManager: true`를 확인하고 저장한다.
4. **이 홈 화면 앱 안에서 다음 주문·알림 동의를 진행한다.** 설치 전 Safari에서 만든 주문으로 시험하지 않는다.

iPhone Web Push는 iOS 16.4 이상 홈 화면 웹 앱에서 사용자 탭에 따른 알림 동의를 지원한다. 알림은 잠금 화면과 알림 센터에서도 확인할 수 있다. [Apple WebKit 공식 안내](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)

## 3. 기기별로 새 주문 생성·알림 동의

1. 테스트 주문 시작 → **QA 테스트 메뉴** 1개 → 장바구니 보기.
2. **매장에서 먹기 → 현금 → 현금 주문하기**를 선택한다. 이름·전화번호는 입력하지 않는다.
3. 완료 화면에서 메뉴, 10,000원, 미결제 상태, 감사 이미지를 확인한다. **주문번호를 적고 화면을 저장한다.**
4. **매장찾기 · 주문진행 확인**을 누른다. 같은 주문번호와 10,000원의 실시간 주문 카드를 확인한다.
5. **준비 완료 알림 켜기** 또는 **페이지 닫아도 알림 받기**를 누르고 OS 알림 요청에서 직접 허용한다.
6. 카드에 **이 페이지를 닫아도 준비 완료 알림을 받아요**가 표시되는지 확인한다. 이 문구가 없다면 종료 시험을 시작하지 않는다. 경고 문구와 환경 확인 화면을 기록한다.

Android와 iPhone에서 **각각 다른 새 주문**을 사용한다. 같은 주문을 재사용하면 이미 수신한 알림의 중복 억제 때문에 시험이 불명확해진다.

## 4. 30초 안에 고객 화면 종료

**Android:** 이 테스트 도메인의 Chrome 탭을 모두 닫고 홈 화면으로 돌아간다. 종료 상태를 화면 녹화에 남긴다. Android 설정의 '강제 중지'는 별도 조건이므로 이 탭 종료 시험과 섞지 않는다.

**iPhone:** 먼저 원래 Safari 테스트 탭을 닫는다. 홈 화면 앱에서 앱 전환기를 열어 **푸시 QA 앱 미리보기를 위로 밀어 종료**하고 종료 장면을 녹화한다. 홈 화면으로 이동만 한 시험은 '백그라운드 수신'으로 별도 기록한다. 강제 종료 조건에서 수신되지 않으면 그 결과를 그대로 기록하며 백그라운드 성공으로 대신하지 않는다.

이후 알림이 올 때까지 테스트 사이트나 앱을 직접 다시 열지 않는다. PC의 테스트 서버는 계속 실행되어야 한다.

## 5. 서버가 자동으로 준비 완료 처리

별도 명령이나 버튼을 누르지 않는다. 주문 접수 시각 + 30초에 서버 타이머가 해당 테스트 주문을 접수 확인 → 조리 중 → 준비 완료로 변경한다. 휴대폰 페이지를 닫아도 서버 타이머는 계속 실행된다. 화면의 카운트다운은 안내용이며, 실제 상태 변경과 푸시 발송은 서버가 수행한다.

알림 활성 문구를 확인하기 전에 30초가 지났거나 페이지를 열어 둔 채 알림을 받았다면 해당 결과는 종료 후 수신 통과로 기록하지 않는다. 새 주문으로 다시 시험한다. Android와 iPhone은 각각 새 주문을 사용한다.

## 6. 실제 푸시 수신과 알림 탭

1. 자동 준비 완료 예정 시각 이후 우선 60초 동안 기다린다. Android 알림창 또는 iPhone 알림 센터·잠금 화면에서 준비 완료 알림을 확인한다. 수신 장면과 시간을 저장한다.
2. **OS 알림 자체를 손으로 탭**한다. 링크 직접 입력이나 홈 화면 아이콘으로 다시 여는 동작으로 대신하지 않는다.
3. 열린 주문 진행 카드에서 **아까 적은 같은 주문번호 / 10,000원 / 준비 완료**를 확인하고 화면을 저장한다.
4. 수신되지 않으면 60초 경과, 화면 종료 방식, 기기/OS, 알림 권한, 집중 모드·방해 금지 상태를 기록한다. 확인을 위해 사이트를 다시 열었다면 이후 알림은 '종료 상태 수신' 증거와 분리한다.
5. 별도 새 주문의 완료 화면에서 매장찾기·네이버·유튜브 세 버튼도 확인할 수 있다. 외부 사이트에는 로그인할 필요가 없다.

화면 녹화는 주문 확인부터 실제 알림 탭 후 주문 카드까지 이어서 남기면 좋다. 개인 메시지·다른 앱 알림이 보이지 않게 하고 필요한 테스트 화면만 공유한다. 증거가 확보되기 전에는 PASS로 기록하지 않는다.

시험 종료 후 테스트 웹 앱에서 알림을 끄고 설치한 푸시 QA 앱을 삭제한다. 테스트 서버는 유효기간까지 실행해 둔다. 만료 후에는 새 링크가 필요하다.
