# 30초 자동 준비 완료 환경 검증

격리 테스트 게이트웨이에서 새 주문 접수 성공 시 주문별 타이머를 예약한다. 예정 시각은 접수 + 30,000ms이며 페이지와 무관하게 서버에서 실행된다. 기존 로컬 운영 스크립트로 테스트 매장·미결제·개인정보 없음 조건을 재확인한 뒤 정상 주문 상태 API를 통해 준비 완료로 전환한다. 카드 승인이나 결제 상태 변경은 하지 않는다.

같은 주문의 생성 응답을 다시 받더라도 이미 등록된 주문의 타이머는 추가하거나 연장하지 않는다. 종료 시 예약된 타이머를 해제한다. 이 기능은 임시 테스트 환경에만 있으며 운영 애플리케이션에는 적용하지 않았다.

## 확인한 범위

- 실제 HTTPS 주문 UI → 서버 알림 구독 → 고객 페이지 모두 닫기 → 30초 예약 실행 → 실제 WNS 푸시 수신.
- PC 수동 준비 완료 명령 없이 실행했다.
- URL 직접 재진입 후 같은 주문번호·10,000원·준비 완료를 확인했다.
- 개인정보 입력과 공개 관리자·카드 승인 경로 차단은 유지한다.
- Windows Edge 환경 사전 점검이다. Android/iPhone의 실제 수신과 OS 알림 탭 성공 증거가 아니다.

정확한 생성·예약·실행·수신 시각과 주문번호는 [results.json](results.json)에 기록한다. [카운트다운](order-auto-ready-countdown.png), [동의 후 종료 전 화면](subscribed-before-page-close.png), [같은 주문 준비 완료](https-test-order-ready.png)를 함께 확인한다.

첫 실행 주문 20261112-0776(ID 15): 접수 2026-11-11T17:09:16.317Z, 예정 17:09:46.317Z, 실행 시작 17:09:46.323Z, 종료 17:09:47.069Z. 고객 페이지는 17:09:19.591Z에 모두 닫았고 예정 시각 약 5.643초 후 실제 푸시를 확인했다. 최종 실행의 상세 결과는 results.json에 저장한다.

현재 휴대폰용 링크와 절차는 상위 [OWN_DEVICE_GUIDE.md](../OWN_DEVICE_GUIDE.md)를 사용한다. 이전 BrowserStack·수동 명령 안내는 당시 실행 이력이며 현재 휴대폰 시험에는 PC 명령이 필요 없다.

운영 경계 확인: [production-isolation.json](production-isolation.json). 운영 `/api/lab/info`는 404이고, 운영 홈에는 테스트 카운트다운이 없다. 운영 주문 쓰기는 0건이며, 실제 런처의 운영·호스팅·외부 DB 실행 거부 테스트와 기존 푸시 단위 테스트 17개가 통과했다.
