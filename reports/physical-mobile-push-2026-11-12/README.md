# Android·iPhone 실제 기기 푸시 검증

> 커밋된 링크·QR은 당시 실행 증거이며 이미 만료될 수 있습니다. 현재 시험은 `node scripts/mobile-push-lab.cjs --isolated-test-only`가 출력하는 새 링크를 사용하세요. 개발자 준비 절차: `scripts/MOBILE_PUSH_LAB.md`.

## 현재 휴대폰 전용 자동 테스트

주문 접수 30초 후 서버에서 자동 준비 완료로 전환한다. PC 명령은 필요 없다. [현재 링크·QR·휴대폰 절차](OWN_DEVICE_GUIDE.md), [자동 전환 사전 점검 증거](auto-ready-preflight/README.md)를 사용한다. 이전 BrowserStack·수동 명령 결과는 당시 실행 이력이다. 실기기 수신·실제 알림 탭은 아직 미검증이다.


상태: **환경 갱신·사전 점검 통과 / 실기기 E2E 미완료**. 이번에는 Galaxy S24(Android 14.0)와 iPhone 15(iOS 17.5)를 실제 연결했으나 각 1분 체험 세션이 URL 입력 중 종료됐다. 사용자가 현재 1분 체험만 이용 가능하다고 확인했다. 푸시 수신·OS 알림 클릭 증거는 아직 없다. [이번 실행 보고서와 화면 증거](session-recheck/REPORT.md), [연결 안내서](REMOTE_SESSION_GUIDE.md)를 확인한다.

갱신한 HTTPS 환경의 Windows Edge 사전 점검은 통과했다. 합성 주문 20261112-3968 / 10,000원 / 결제 pending, 페이지 종료 후 실제 WNS 푸시 수신 9.719초, URL 직접 재진입 후 같은 주문 준비 완료를 확인했다. 카드 공급자 요청은 0건이고 DB에서도 이름·전화번호 없음과 CASH READY를 확인했다. 실제 기기 및 OS 알림 클릭 결과를 대신하지 않는다.

## 실행 조건

- 실제 Android 및 iPhone의 기종·OS 버전·브라우저 버전을 기록한다. 에뮬레이터와 모바일 화면 크기 변경은 제외한다.
- 테스트 전용 매장·합성 계정과 격리 DB/API만 사용한다. 운영 고객 주문이나 연락처를 조회하지 않는다.
- 카드 결제·자동 구독 결제 대신 미결제 테스트 주문을 사용한다. 주문 상태 변경은 테스트 점주 계정에서만 수행한다.
- 기기에서 접근 가능한 테스트 전용 HTTPS 주소가 필요하다. 최소 API만 허용하는 임시 HTTPS 게이트웨이를 준비했다. 운영 API와 점주 로그인은 공개하지 않으며 연결 안내서의 유효기간을 확인한다.
- iPhone은 홈 화면에 추가한 웹 앱에서 알림을 허용한다. Android도 사용 브라우저와 알림 허용 상태를 기록한다. 개인 알림이나 계정 정보는 증거에 포함하지 않는다.

## 기기별 실행 순서

1. 테스트 매장 메뉴에서 합성 주문을 생성하고 주문 번호·금액·미결제 상태를 확인한다.
2. 매장찾기의 해당 주문 카드에서 준비 완료 알림을 직접 허용한다. 서버 구독 성공을 확인한다.
3. 테스트 페이지를 모두 닫는다. iPhone 홈 화면 앱의 경우 앱 화면을 나간 상태를 기록하고, 강제 종료 시험은 별도 항목으로 구분한다.
4. 별도 테스트 점주 화면에서 동일 주문을 접수 확인 → 조리 중 → 준비 완료로 변경하고 시각을 기록한다.
5. 기기 네이티브 알림의 도착 시각과 화면을 수집한다. 브라우저 내부 showNotification 호출이나 push 이벤트 주입으로 대신하지 않는다.
6. 실제 네이티브 알림을 손으로 또는 실기기 UI 자동화로 누른다. notificationclick 이벤트 주입과 URL 직접 입력은 제외한다.
7. 열린 주문 진행 화면에서 동일 주문 번호·금액·준비 완료 상태를 확인하고 화면을 수집한다. 기존 저장 권한으로 복구되는지도 확인한다.
8. 같은 주문의 상태 재조회·새로고침에 알림이 중복되지 않는지 확인한다. 종료 후 테스트 주문 상태와 테스트 구독을 정리한다.
