# 웹앱 첫 접속 및 페이지 이동 개선

## 확인한 병목과 수정

1. Icon.tsx의 전체 lucide-react 네임스페이스 조회가 아이콘 카탈로그 전체를 초기 다운로드에 포함했습니다. 실제 사용하는 이름을 명시한 iconRegistry.ts로 변경했습니다. 새로운 문자열 아이콘을 추가할 때 등록 파일에도 추가해야 합니다.
2. 방문하지 않은 관리자 화면·차트·PDF·엑셀 라이브러리까지 서비스 워커 설치 시 미리 받았습니다. 초기 HTML이 참조하는 JS와 기본 정적 파일만 사전 캐시하고, 추가 화면은 방문할 때 내려받아 캐시합니다. 애니메이션 라이브러리의 강제 공통 청크도 제거했습니다.
3. main.jsx와 usePWAUpdate가 업데이트 처리를 중복 관리했습니다. 첫 컨트롤러 변경, 설치 완료, 주기적 갱신에 따른 강제 새로고침을 제거하고 기존 업데이트 버튼에 제어를 통합했습니다. 정상 설치·업데이트 때문에 주문 화면을 자동 재시작하지 않습니다. 실제 청크 로딩 오류의 제한된 복구 처리는 유지합니다.
4. 모든 503을 Render 휴면으로 취급해 API 키 미설정 응답도 최대 60초 기다렸습니다. JSON 503은 즉시 전달합니다. 취소한 요청을 다시 실행하지 않고, 주문·결제처럼 이미 서버에서 처리됐을 수 있는 쓰기 요청은 자동 재전송하지 않습니다. 안전한 GET/HEAD의 네트워크·게이트웨이 오류는 한 번 복구합니다.
5. 서버 웨이크업 실패의 미처리 Promise와 실패 시 남는 타이머를 정리했습니다.

## 실제 빌드 비교

| 항목 | 변경 전 | 변경 후 |
|---|---:|---:|
| HTML이 참조하는 초기 JS+CSS gzip 합계 | 444,728 B | 256,252 B |
| 초기 아이콘 청크 원본 | 623,956 B | 54,616 B |
| 서비스 워커 사전 캐시 | 149개 / 약 5,528 KiB | 15개 / 약 987 KiB |

초기 압축 다운로드 약 42%, 서비스 워커 사전 캐시 약 82% 감소. 이 수치는 실제 빌드 파일 비교이며 실사용 접속 시간 개선율을 의미하지 않습니다.

## 검증 결과

- coldStart·startup·기존 CSRF 테스트 총 27개 통과.
- 프로덕션 빌드 및 300KB gzip 초기 다운로드 예산 검사 통과.
- 실제 로컬 서비스 워커 설치: 첫 방문 문서 요청 1회, 자동 재로딩 없음, 미방문 관리자 JS 다운로드 없음.
- 느린 API fixture를 사용한 QR 캐시 재방문: 저장된 메뉴 1,100ms, health 완료 전에 표시, 이후 최신 메뉴로 갱신.
- AI 매니저 브라우저 검사: 1440px·390px 승인/실행·성과·대화·QR 추천 모두 정상, 오류와 가로 넘침 없음.
- 변경 JS ESLint 오류 없음. TS 파일은 기존 ESLint 설정의 검사 대상이 아니므로 lint 검사 범위에서 제외됨.
- CI 브라우저 잡에 초기 다운로드 예산 및 서비스 워커 첫 방문 회귀 검사를 추가했습니다. 이번 변경의 원격 CI 실행은 아직 수행하지 않았습니다.

## 운영과 남은 한계

기존 wemarket-saas Vercel 프로젝트에 프런트엔드 수정본 배포를 완료했습니다. 배포 ID dpl_7hEzP2E6k7eNwDPsA81HWVCrMdgW, 상태 READY, 운영 URL https://wemarket-saas.vercel.app. 운영 HTML·JS·CSS·sw.js 모두 HTTP 200, 전체 아이콘 카탈로그 제거와 미방문 관리자 사전 캐시 제거를 재확인했습니다. 로컬/운영 빌드 타임스탬프와 CSS 파일명은 빌드 환경에 따라 다릅니다.

Render 코드·DB·요금제는 변경하지 않았습니다. 휴면 서버의 첫 실시간 데이터 응답은 여전히 지연될 수 있습니다. 처음 방문하여 메뉴 캐시가 없는 고객에게 최신 메뉴를 서버 응답 없이 제공할 수는 없습니다. 재방문 캐시를 표시할 때 기존 최신 가격·품절 확인 표시를 유지합니다.

기존 전체 사전 캐시보다 오프라인에서 처음 방문하는 페이지의 범위가 줄어듭니다. 이미 방문하여 캐시된 화면은 유지됩니다. GitHub main에는 이번 수정본을 아직 게시하지 않았으므로, 이후 Git 기반 배포 전에 로컬 변경 파일을 함께 반영해야 합니다.
