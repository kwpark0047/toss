## 상태와 데이터

- `Subscription`: 이용 상태·기간·자동 갱신·암호화된 결제수단·동의 기록.
- `BillingInvoice`: 서버 확정 가격, 기간, PG 주문 번호, 처리 상태와 시도 횟수. `(subscription_id, period_start)`와 `order_id`가 고유하다.
- `IdempotencyRecord`: 본문 해시·요청 상태·응답. 금융 처리 결과가 불명인 기록을 자동 삭제하거나 재실행하지 않는다.
- `point_transactions.reversal_of`: 원본 내역별 복구를 한 번만 허용하는 고유 키. 현장 결제 환불은 실제 환불 완료 확인을 요구하고 기록·포인트·재고를 트랜잭션으로 반영한다. 현장 결제와 포인트의 부분 환불은 지원하지 않는다.
- 기존 `stores.plan`, `store_subscriptions`는 검증된 구독 상태에 맞춰 호환 데이터를 갱신한다. 기능 판정은 `Subscription`의 유효 기간과 상태를 기준으로 한다.

`auto_renew`의 기본값은 false다. 기존 구독에 새 자동 과금을 일괄 시작하지 않는다. 신규 카드 인증과 최초 결제가 성공한 구독만 명시적으로 true를 기록한다. 기존 유료 고객의 이용 기간과 결제수단은 별도로 대조하고 갱신 동의를 받아야 한다.

청구 실패는 최대 3회까지 처리한다. 처리 작업의 2분 lease가 지나면 같은 PG 주문 번호로 확인하지만, 마지막 시도의 결과가 불명인 경우 `manual_review`로 전환한다. Toss의 주문 번호·결제 내역과 대조하기 전 해당 기록을 삭제하거나 새 주문 번호로 청구하지 않는다. 자동 환불·결과 불명 청구서의 강제 확정 UI는 구현 범위에 포함하지 않았으며 운영자가 PG 내역과 대조해야 한다.

월간 한도는 UTC 월초 기준이다. 오프라인 주문은 서버 수신 시각으로 한도를 집계하고 원래 수납 시각을 메모에 보존한다. 과거 공개 증빙은 접근을 차단했으며 비공개 버킷으로의 실제 파일 이전은 실행하지 않았다.

## 운영 적용 순서

1. 별도 스테이징 DB에서 백업 및 기존 구독·플랜·공개 증빙 현황을 확인한다.
2. `prisma/migrations/20261006000000_commercial_saas_billing/migration.sql`을 포함한 대기 마이그레이션을 스테이징에 적용한다. 운영 적용 전 기존 마이그레이션 이력과 드리프트를 확인한다.
3. Toss 정기결제 이용 계약과 해당 환경의 `TOSS_CLIENT_KEY`, `TOSS_SECRET_KEY`를 설정한다. 강한 `JWT_SECRET`과 별도의 `TOKEN_ENC_KEY`를 관리한다. 키를 변경할 때 기존 암호화 토큰의 복호화 가능성을 유지해야 한다.
4. `STORAGE_DRIVER=supabase`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_PRIVATE_BUCKET=payment-proofs`를 설정한다. 버킷은 public=false여야 한다. 기존 증빙의 비공개 이전을 완료한다.
5. 가입·실패·동시 재시도·갱신·해지·재개·플랜 변경·다른 매장 접근 차단을 스테이징 DB와 Toss 테스트 환경에서 검증한다. 기존 고객 데이터와 실제 PG 승인 결과는 이번 로컬 검증에 포함하지 않았다.
6. 실사용 사업자 정보, 이용약관·개인정보·해지 및 환불 정책, 고객 문의 창구, 과금 알림과 장애 대응 담당자를 확정한다. 구현한 동의 문구는 서비스의 실제 정책과 일치하도록 확인해야 한다.
7. 검증·승인 이후 운영 DB와 서비스를 배포한다. 갱신 작업을 수행할 운영 인스턴스에서만 `BILLING_SCHEDULER_ENABLED=true`를 설정한다. Render 무료 인스턴스의 휴면 시간에는 갱신 작업이 실행되지 않으므로 상시 실행 서비스가 필요하다.

`render.yaml`은 `autoDeploy=false`, 자동 갱신 scheduler=false로 준비했다. CI를 통한 배포도 테스트·보안 검사 뒤에 실행되도록 연결했다. 외부 대시보드의 기존 자동 배포 설정을 이번 작업에서 변경하지는 않았다.

Vercel 배포·환경 변수·로그 확인에는 로컬 Vercel CLI가 필요하다. 설치 명령은 `npm i -g vercel`이며 이번 작업에서는 글로벌 설치나 배포를 실행하지 않았다.
