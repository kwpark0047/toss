# 대시보드 UI/UX 및 로그인 개선

## 변경

- 기존 tds-stack 공통 CSS가 관리자 레이아웃을 세로로 강제하던 문제를 제거했다. 데스크톱은 240px 사이드바와 본문을 나란히 배치한다.
- 헤더·내비게이션·사용자 메뉴를 간소화하고 매출·주문·완료율·대기 상태를 첫 화면에 배치했다. 선택한 매장의 관리 메뉴가 대시보드에서도 표시된다.
- 모바일 하단 탐색, 전체 메뉴의 Escape 닫기·초점 복귀·Tab 이동, 본문 바로가기와 활성 메뉴 안내를 제공한다.
- 밝은/어두운 테마의 상태 카드·본문 대비를 통일하고 작은 텍스트의 가독성을 개선했다. 관리자 화면을 가리던 앱 설치 팝업은 해당 화면에서 표시하지 않는다.
- 임의의 키오스크 3/3 정상 표시는 제거했다. 실제 health 응답의 API·DB 상태와 응답 시간·확인 시각을 표시한다.
- 매출 차트가 실제 분석 API의 summary/data 응답을 읽도록 수정했다. 주문 상태는 비교하기 쉬운 가로 막대로 표시한다. 차트 진입 애니메이션을 제거했다.
- 데이터 실패 경고와 재시도 동작을 추가했다. 화면이 숨겨졌을 때 불필요한 조회를 줄이고, 겹친 응답이 최신 선택을 덮어쓰지 않도록 했다.
- 주간·월간 필터를 실제 매출 통계 조회에 연결했다. 주문 날짜 경계와 시간별 집계는 한국 시간 기준으로 통일했다.
- 주문 목록의 중복 레거시 DataLoader 호출을 제거하고 Repository가 이미 조회한 아이템·결제를 사용한다.
- 로그인 identifier 요청과 서버 검증 규칙을 일치시켰다. 로그인·2FA의 401은 세션 갱신이나 다른 화면으로 이동시키지 않고 원래 오류를 표시한다.

## 검증

- 로그인·주문·구독 회귀 테스트 25개 통과.
- 로그인 폼·인증 클라이언트 테스트 22개, 차트 데이터 테스트 2개 통과.
- 백엔드 타입 검사 및 변경 코드 정적 검사 통과.
- 프런트엔드 운영 빌드 통과.
- 실제 Chromium: 1440px 밝은/어두운 화면, 390px 모바일, 메뉴 닫기·초점 복귀, 데이터 오류 상태 검증. pageerror 0, 가로 넘침 0.
- 테스트 화면의 매출·주문 숫자는 격리된 fixture다. 모든 API·소켓을 대체하므로 운영 데이터나 계정으로 검증했다고 해석해서는 안 된다.
- CI에 production 번들의 관리자 브라우저 검사도 추가했다.

운영 사용자 계정의 비밀번호를 사용하지 않았다. 운영 반영 후 로그인 폼과 인증되지 않은 주문 경로를 별도로 확인한다.
