# 최고관리자 AI 사업자 성장 지원센터 제안

## 목표와 현재 기반
최고관리자가 '어느 매장에 도움이 필요한가'를 파악하고, 사업자에게 실행 가능한 지원안을 전달하며 승인·실행·효과를 추적하는 지원센터를 제안한다. 단순 매출 순위나 자동 광고 발송이 목표가 아니다.

확인한 코드: services/StoreManagerService.js, utils/storeManagerAnalysis.js, frontend/src/components/admin/AIStoreManager.jsx. 현재 매장별 자체 주문/환불, 상품, 리뷰, 외부 수집 상태·canonical 근거를 분석하고 snapshot/action/승인/실행/성과 비교를 관리한다. 5분 snapshot, 분석 기간/출처, 표본 부족 처리가 있다. 현재 QR 메뉴 노출 지원은 7일이며 할인·문자 발송과 구분되어 있다. 플랫폼 전체의 지원 우선순위·담당자·사업자 협업·지원 사례 관리는 추가 설계가 필요하다. 실제 업체 연동 완료를 가정하지 않는다.

## 사업자에게 실질적으로 도움이 되는 우선 기능
| 우선순위 | 지원 기능 | 확인할 근거 | 사업자에게 제안할 행동 | 효과 지표 |
| --- | --- | --- | --- | --- |
| 1 | 오늘 매출 이상 조기 대응 | 같은 요일·같은 경과 시간의 순매출/결제 주문, 수집 지연 | 영업 상태·품절·메뉴 노출·QR 접속 확인 체크리스트 | 회복한 주문·순매출, 대응 시간 |
| 1 | 주문 누락·주방 병목 지원 | 접수/조리 상태 체류 시간, 취소 사유, 영업시간 | 미접수 주문 확인, 예상 대기시간 조정, 담당자 배정 | 접수 시간, 취소율, 고객 대기 |
| 1 | 인기 메뉴 품절 예방 | 판매 속도, 실재고, 입고 예정, 재고 신선도 | 사업자가 확인할 발주 초안·대체 메뉴 안내 | 품절 시간, 기회손실, 폐기율 |
| 2 | 매출보다 이익 개선 | 순매출, 할인, 원가, 수수료, 판매 구성 | 원가율 높은 메뉴 점검, 수익성 높은 세트/메뉴 노출 | 공헌이익, 원가율, 할인 후 객단가 |
| 2 | 한가한 시간대 매출 지원 | 충분한 동일 요일 시간대 표본, 좌석/조리 여력 | 제한된 기간·수량의 프로모션 초안 | 해당 시간 순매출, 마진, 증가 주문 |
| 2 | 단골 재방문 지원 | 동의된 고객 집계, 방문 간격, 재구매율 | 대상 규모와 예상 비용을 제시한 쿠폰/메시지 초안 | 재방문율, 비용 대비 순이익, 수신 거부 |
| 2 | 정산 차이 해결 지원 | POS/배달/PG 원장, 매핑·환불·입금 기간 | 원장 차이 목록과 확인 순서, 누락 자료 요청 | 미해결 차이 금액·건수, 해결 기간 |
| 3 | 리뷰·운영 품질 개선 | 본인 매장 리뷰, 응대 시간, 반복 불만 집계 | 답변 초안, 개선 체크리스트, 후속 점검 | 반복 불만, 응대 시간, 후기 개선 |

원가·실재고·입금 데이터가 없으면 수익성/발주/정산을 추측하지 않는다. 추가 자료 요청이나 입력 안내로 전환한다. SMS가 미설정이면 앱 내 지원 제안까지만 제공한다.

## 최고관리자 화면
기존 대시보드에 'AI 사업자 지원센터' 진입을 추가한다.

1. **지원 요약**: 지원 대상 매장, 긴급 대응, 사업자 승인 대기, 실행 중, 성과 확인 예정. 공개 수집 매장 수와 실제 지원 가입 매장 수를 별도로 표시한다.
2. **우선 지원 목록**: 매장·영향·신뢰도·최신 데이터 시각·담당자·상태. 금액과 원인 근거를 함께 보여주며 오래된 자료에는 지연 표시를 한다.
3. **매장 지원 패널**: 오늘 요약, 비교 기준, 데이터 출처, 문제, 실행안, 비용/할인 한도, 사업자에게 제안, 승인 상태, 결과.
4. **지원 이력·성과**: 어떤 문제에 무엇을 제안했고 사업자가 무엇을 실행했는지 추적. 플랫폼 지원 활동 수와 매장 개선 효과를 구분한다.

사업자 대시보드에는 '오늘의 매장 매니저'와 '위마켓 지원 제안함'을 제공한다. 제안을 승인·수정 요청·보류·거절할 수 있고, 실행 후 원복/중단 경로도 제공한다.

## 실행 흐름과 책임
데이터 수집 → 품질 검사 → 규칙 기반 탐지 → 근거 snapshot → AI 설명/행동 초안 → 최고관리자 검토 → 사업자 제안 → 사업자 승인 → 허용된 실행 → 성과 평가.

- 최고관리자는 검토·지원 담당자 배정·설명·초안 제안을 담당한다. 사업자 승인 없이 할인, 문자, 광고, 발주, 지급을 실행하지 않는다.
- 대행 실행이 필요하면 사업자가 작업 종류·매장·한도·기간을 명시해 위임한다. 최고관리자 역할 자체를 위임으로 간주하지 않는다.
- 주문/결제 상태나 매출 원장을 AI 판단으로 수정하지 않는다. 현금 미수금 주문은 수금 매출로 취급하지 않는다.
- 각 행동은 operation ID·상태 전이·권한·중복 실행 방지·감사로그·중단 조건을 가진다. 같은 제안을 재시도해도 한 번만 실행한다.

## 실시간 구조와 확장성
실시간은 '변화 감지'와 'AI 설명 생성'을 분리한다. 주문/입고/환불/외부 동기화 완료 이벤트는 수초~수십 초 내 표시를 목표로 하고, 분석은 기존 5분 snapshot을 기본으로 한다. 긴급 이벤트는 우선 처리한다. 매 주문마다 LLM을 호출하지 않는다.

현재 약 15만 건의 매장 레코드를 모두 5분마다 분석하면 DB·AI 비용과 오탐이 커진다. **사업자 연결·지원 동의·운영 데이터가 있는 매장만** 대상 등록하고, 변경이 있는 매장의 dirty queue를 처리한다. 공개 공공데이터 매장을 실제 서비스 운영 매장으로 간주하지 않는다.

worker는 매장별 동시 실행 제한, 전역 DB/AI 처리량 제한, retry/backoff, DLQ, timeout, 비용 예산을 가진다. 최고관리자 첫 화면은 저장된 지원 요약을 읽고 필요한 매장만 상세 조회한다. 외부/AI 실패는 주문·결제 기능에 전파되지 않는다. 웹소켓은 해당 매장 권한을 검사하며 끊기면 제한된 polling으로 복구한다.

## 근거·금융·개인정보 기준
- 자체 매출은 수금 확인·환불을 반영한 순매출을 기준으로 삼고 원장과 대사한다. 주문액, 순매출, 입금액, 구독 MRR를 혼합하지 않는다.
- 동일 주문이 POS/PG/배달 자료에 중복 유입돼도 중복 매출로 합산하지 않는다. provider/account/mapping/event ID와 기준 기간을 보존한다.
- 관측 시간대는 Asia/Seoul, 비교는 같은 요일·같은 경과 영업시간으로 한다. 휴무·휴일·날씨는 해당 데이터가 확보된 경우만 사용한다.
- 모든 추천에 store_id, 분석 기간, 데이터 기준시각, provider, snapshot, 지표/비교 기준, 모델/규칙 버전, 신뢰도·품질 상태를 붙인다.
- 기존 분석은 비교 요일 4개/기준 주문 30건 미만 등에서 표본 부족을 처리한다. 최초 출시에서는 이를 유지하고 매장별 표본 기준은 검증 후 조정한다.
- tenant 데이터는 매장별로 분리한다. 고객 전화번호·결제 식별자·리뷰 내 민감정보를 LLM에 원문으로 전달하지 않는다. 집계된 고객 군만 사용하며 마케팅 동의를 확인한다.
- 외부 리뷰/CSV의 문장은 데이터로 취급하고 지시문으로 실행하지 않는다. 구조화 출력과 허용 행동 목록을 검증한다.

## 성과 측정
승인된 제안마다 기준 기간·대상 메뉴/시간·평가 시각·주 지표·비용을 먼저 고정한다. 순매출뿐 아니라 할인·수수료·원가·취소·민원 악화도 함께 본다. 단순 전후 상승을 AI의 인과 효과로 선언하지 않는다. 같은 요일/시간 비교 또는 가능한 통제군을 사용하고 표본 부족·외부 이벤트 영향을 표시한다.

사업자 보고 예시(실제 측정값이 아닌 형식 예시): '지난 제안은 승인 후 7일간 실행됐습니다. 같은 요일 기준 메뉴 판매량은 증가했지만 할인 비용을 반영한 이익 효과는 아직 판단할 표본이 부족합니다.'

## 도입 순서
1. **읽기 전용 지원센터**: 대상 등록·순매출/품절/주문 지연 탐지·근거 패널·담당자·사업자 제안함. 실제 금융/외부 실행 없음.
2. **승인형 지원**: 기존 QR 추천 노출 재사용, 작업별 승인·한도·중복 방지·중단·감사 이력, 성과 비교.
3. **원가·재고·정산 확장**: 매입 기획의 발주/검수/원가 구조와 연결. 실제 업체 원장으로 매출/정산 대사.
4. **동의 기반 CRM**: 운영 SMS/알림 제공자 검증 후 제한된 발송, opt-out·비용·빈도·성과 관리.

초기 파일럿은 데이터가 충분한 실제 운영 매장을 소수 선정한다. 성공 기준은 대응 시간, 사업자 제안 수용률, 문제 해결률, 실제 비용 반영 성과와 오탐률이다. 매장 격리·무승인 실행 차단·중복 처리·장애 복구·표본 부족·원장 일치·화면 E2E를 출시 게이트로 한다.

## 제안의 상태
이번 산출물은 기획 제안이다. AI 지원센터 코드·DB·자동 실행 기능을 새로 구현하거나 운영 활성화하지 않았다. 데이터 출처와 업체 연결은 코드 준비/운영 검증 상태를 분리한다.
