# 고객 채팅 키 재노출 보완

사용자는 현재 테스트 도메인에서 chat.manager_title, chat.live_support가 보인다고 보고했다. 서버의 최신 HTML/번들과 새 브라우저 화면은 이미 한국어를 표시했다. 사용자 브라우저의 실제 캐시·서비스워커 상태에는 직접 접근하지 못했으므로 그것을 확정 원인으로 단정하지 않는다.

## 재현과 수정

- 실제 ChatDrawer에 chat 번역 리소스가 없는 i18next 인스턴스를 공급하면 제목·상담 안내·입력창에 키가 노출되는 것을 재현했다. 회귀 테스트가 수정 전 실패했다.
- 각 t 호출에 한국어 defaultValue를 추가했다. 리소스 누락 상태에서도 다섯 문구를 표시하며, 제공된 외국어 번역은 그대로 우선한다.
- 수정 후 컴포넌트 테스트 2개와 기존 다국어 회귀 테스트 4개, 총 6개가 통과했다.
- 격리 브라우저에서 같은 테스트 도메인의 이전 정적 번들을 유지하면 같은 키 노출을 재현했다. 최신 번들로 새로고침하면 한국어가 복구되고 localStorage의 합성 표식도 보존됐다. 이 실험은 서비스워커를 차단한 제어된 구버전 번들 재현이며, 사용자 캐시의 직접 조사 또는 실제 휴대폰 검증은 아니다.

## 보존 범위

전체 캐시 삭제, localStorage/sessionStorage 초기화, 서비스워커 강제 해제, 푸시 구독 해제를 추가하지 않았다. 채팅 문구만 보완한다. 기존 PWA는 사용자가 업데이트를 선택하거나 모든 탭을 닫은 뒤 새로 열어 최신 코드를 사용한다. 이미 실행 중인 이전 JavaScript는 소스 배포만으로 바뀌지 않는다.
