# 위마켓 가입·보존·구독 정책 권장안

작성일: 2026-10-15, 2026-10-17 갱신 / 상태: 일부 사용자 결정 반영, 미공표 검토안

이 문서는 운영자가 선택할 정책안이다. 현재 기능·계약·법적 의무가 모두 충족됐다는 의미가 아니다. 법령상 보장되는 권리는 아래 운영 기준보다 우선하며, 소비자 거래와 사업자 계약의 적용 범위를 최종 검토한다. 운영자 신원·연락처는 별도 확정한다.

## 1. 가입 허용 연령

사용자 결정: 신규 플랫폼 회원가입은 **만 14세 이상, 상한 없음**으로 제한한다. 사업자·직원 권한은 연령 확인과 별도로 검증한다. 이는 가입자의 자기 확인이며 신원·휴대전화·사업자 자격 확인을 뜻하지 않는다.

- 이메일·Google·카카오는 계정 소유 확인 수단이며 연령·실명·사업자 본인확인을 증명하지 않는다.
- 초기에는 생년월일·주민등록번호를 수집하지 않고 '만 19세 이상' 확인과 정책 버전·확인 시각만 기록하는 최소 수집안을 우선 검토한다. 자기 확인은 법적 연령 검증을 대체하지 않으므로 별도 검증 의무가 있는 기능에는 사용하지 않는다.
- QR 비회원 메뉴 조회·주문은 회원가입 정책과 별도다. 미성년자의 구매, 법정대리인 권리 및 연령 제한 상품은 별도 정책·화면·사업자 책임을 검토한다.
- 만 14세 미만의 개인정보 처리 동의 절차는 별도 구현·검토 전 제공하지 않는다. 비회원 QR 메뉴·주문과 플랫폼 회원가입은 별개 기능이다.
- 로컬 코드에는 가입 화면·API 양쪽의 14세 확인, 약관 동의 검증, 동의 버전 기록이 구현되었고 격리 DB에서 회귀 테스트했다. 이 migration은 운영 미적용이며 실제 배포·운영 검증 전에는 운영 연령 통제가 활성화됐다고 말하지 않는다.

## 2. 개인정보 보존·파기

### 권장 보존표

| 정보 | 제안 기준 | 현재 상태 및 적용 전 조건 |
| --- | --- | --- |
| 이메일 OTP·링크 | 사용 가능 5분. 검증은 해시, 발송 payload는 발송 수락/불확실 시 제거 | 코드에 존재. 5분 만료와 기록 삭제는 별개 |

| 법정 거래 기록 | 적용 대상에 한해 계약/철회·결제/공급 5년, 불만/분쟁 3년, 표시/광고 6개월 기준 검토 | 세무 등 다른 의무 포함 실제 적용 확정. 모든 고객 데이터를 일괄 보존하지 않음 |
| AI 입력·결과 및 연동 원본 | 원본 최소 수집, 신규 원본 보관 기본 30일 이내 제안. 장기 통계는 적법한 비식별/집계와 필요성 검토 | 모델 공급자 보존·매장 계약·재식별 위험 확인 전 확정 금지 |
| 백업 | 일일 백업·최대 35일 순환 보관 목표 | 실제 요금제/PITR·지역·보존 설정·복구 시험 미확인. 즉시 완전 삭제 보장 금지 |

위 기간은 일괄 신규 법적 근거가 아니다. 개별 목적·근거와 최소성을 검토하고 보존 의무가 없으면 목적 달성 후 불필요하게 유지하지 않는다. 분쟁·보안 조사 보존 예외는 대상·사유·기한·승인·접근자를 기록하고 종료 시 파기한다.

### 운영 절차 권장

1. 개인정보 목록에 항목·목적·근거·보유 기간·삭제 작업·책임자를 연결한다.
2. 만료 판정은 서버 UTC로 계산하고 이용자에게는 한국시간으로 표시한다. 배치 경계·윤년·중복 실행을 테스트한다.
3. 정리 작업을 하루 1회 실행하고 삭제 건수·성공 시각·오류 코드만 기록한다. 원문 이메일·토큰·OTP는 로그에 남기지 않는다.
4. 보존 대상은 활성 서비스와 논리적으로 분리하고 제한된 역할만 접근하게 한다.
5. 백업 복구 후 삭제/탈퇴 대상 목록을 다시 적용해 삭제 계정이 되살아나지 않게 검증한다. 삭제 목록 자체도 최소 식별자·기간·접근 통제로 관리한다.
6. 열람·삭제 요청을 접수할 실제 창구와 담당자를 지정하고 법정 기한에 맞는 처리 절차를 확정한다.

완료 조건: dry-run 대사 → 격리 DB 만료 전후·재실행 테스트 → 승인된 운영 예약 → 실행/경보 증거 → 백업 복구 후 재삭제 시험. **지금 운영 정리 작업을 켜거나 운영 데이터를 삭제하지 않는다.**

## 3. 구독 해지·환불

### 신청·자동 갱신

- 월 구독부터 시작하고 가격·부가세·기능·청구 주기·갱신일·해지 경로를 결제 직전에 표시한다.
- 자동 갱신은 별도 명확한 신청 절차로 확인하고 결제수단 등록만으로 신청한 것으로 보지 않는다.
- 갱신 3일 전 안내를 권장한다. 가격 인상·연간 계약은 별도 사전 고지와 필요한 동의를 적용한다.
- 기본 해지는 **다음 갱신 중지**다. 접수 즉시 자동 갱신을 끄고 이미 결제한 기간 끝까지 이용을 허용한다. 종료 일시와 다음 청구 없음 상태를 화면·확인 메시지로 남긴다.
- 해지와 계정 탈퇴는 별개이며 해지했다고 과거 거래 기록을 즉시 삭제하지 않는다. 해지 요청을 고객센터 연락에만 의존시키지 않고 대시보드에서 제공한다.

### 권장 환불 기준

| 상황 | 제안 처리 |
| --- | --- |
| 중복·오청구 또는 승인되지 않은 결제 확인 | 해당 잘못된 청구 전액 환불, entitlement·원장 함께 대사 |
| 결제 후 7일 이내 미사용 | 전액 환불을 기본 제안. 법정 청약철회 요건·예외·고지 및 사업자 거래 해당 여부는 별도 검토 |
| 정상 사용 후 즉시 종료 요청 | 실제 납부한 해당 이용료의 미사용 기간 일할 환불 제안. 법정 권리보다 불리하게 제한하지 않음 |
| 기간 종료 예약 해지 | 잔여 기간 이용 후 종료. 별도 즉시 종료·환불 신청은 위 기준으로 처리 |
| 서비스 제공 불가·중대한 장애 | 미제공 기간 환불/보상, 계약 이행 불가 시 미사용 잔액 환불. 구체적 장애 기준은 서비스 수준 정책으로 확정 |
| 이미 환불한 거래의 재요청 | 추가 중복 환불 없이 누적 확정액·남은 결제액 확인 |

일할 환불 제안식: `min(남은 결제 잔액, floor(해당 기간 실납부액 × 미사용 기간 / 전체 이용 기간))`. 동일 기간 단위·KRW 1원 기준을 사용하고 VAT·할인·쿠폰·이전 부분 환불을 함께 대사한다. 결제 시작·종료 시각과 환불 효력 시각을 명확히 표시한다. 연간 할인·크레딧·사용량 과금의 환불은 별도 확정 전 출시하지 않는다.

환불 승인 후 가능한 한 3영업일 이내 PG 취소 요청 처리를 목표로 하되, 실제 처리 의무·기한 및 카드사/은행 입금 소요를 구분해 안내한다. 단순히 '사용했으므로 무조건 환불 불가'라고 공표하지 않는다.

### 실패·재시도 권장

- 결제 실패 시 미납 상태와 재시도 예정일을 안내한다. 기존 결제 성공·잔여 기간 권한을 오류로 회수하지 않는다.
- 동일 invoice에 대해 실패 후 1·3·5일 재시도, 7일 유예 종료안을 제안한다. 매 시도 전 갱신 해지·이미 결제됨·동일 청구 멱등키를 검사한다. 실제 청구 상태가 불확실하면 조회·대사부터 한다.
- 유예 종료 시 유료 기능만 제한하고 본인 매장의 과거 데이터 열람·내보내기 및 정산/해지 접근은 별도 제공한다. 핵심 주문 흐름 영향은 제품 정책으로 먼저 확정한다.
- 환불은 요청 operation ID, PG 확정 상태, 원장·이용 권한 반영을 재시작 후에도 대사한다. PG 성공/DB 실패 시 무조건 재취소하지 않는다.

### 현 코드와의 차이·검증

services/SubscriptionService.js의 cancelSubscription은 기간 말 해지 기본값과 auto_renew=false 갱신을 포함한다. 그러나 위 전체 정책, 알림 일정, 일할 환불, 보존 기간 및 유예 처리가 모두 같은 계약으로 구현·운영 검증됐다고 판단하지 않는다. 실제 라우트·scheduler·청구 서비스·권한 소비 경로를 함께 감사한 뒤 승인된 정책만 반영한다.

완료 조건: 청구 직전 해지와 scheduler 경합, 중복 webhook, 지연 PG 응답, 부분 환불 후 재환불, DB 실패·재시작, 권한 만료 경계, 실제 PG sandbox, 대시보드 확인 E2E. 운영 결제·환불은 별도 특정 거래 승인 없이는 실행하지 않는다.

## 승인·활성화 순서

이 권장안 선택/수정 → 운영자 신원·지원/보호책임자 확정 → 계약·수탁·국외 이전 정보 확정 → 코드 차이 수정 및 테스트 → 최종 문서/버전 게시 → 실제 staging OAuth·Turnstile·OTP 검증 → 활성화 판단.

사용자는 기본 보존·파기 및 해지·환불 기준을 적용하라고 요청했으며, 이를 실제 코드·계약·법적 보존 의무와 대조해야 한다. 본 문서의 미검증 제안은 공표된 확정 약속이 아니다. 무료 인증 운영 flag는 false 유지한다. 본 문서는 회원 동의, 운영 데이터 삭제, 실결제·환불 실행 또는 별도 운영 적용 승인이 아니다.
