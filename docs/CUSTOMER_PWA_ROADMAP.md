# 고객용 WeMarket PWA 개선 계획

작성일: 2026-10-30
범위: 공개 QR 메뉴, 고객 주문·주문 상태 화면, 모바일 PWA 경험

## 목표

QR을 스캔한 고객이 설치나 로그인 없이 메뉴를 빠르게 확인하고 주문할 수 있게 한다. 설치를 선택한 고객은 다음 방문과 주문 상태 확인을 더 편하게 이어가되, 오프라인 주문·결제의 중복이나 접수 오인을 막는다.

## 현재 구현 확인

| 영역 | 현재 코드 | 판단 |
|---|---|---|
| 앱 설치 기반 | `frontend/public/manifest.json`에 standalone, 아이콘, 앱 메타데이터가 있음 | 기본 준비됨 |
| 서비스 워커 | `frontend/vite.config.js`가 앱 셸·정적 자산·이미지 캐시와 업데이트 확인을 구성 | 기본 준비됨 |
| 설치 안내 | `frontend/src/components/common/PWAInstallBanner.jsx`가 `/menu/` 고객 QR 경로에서 설치 배너를 숨김 | QR 고객의 적절한 설치 시점이 없음 |
| 오프라인 메뉴 | `MenuPage`가 공개 매장 메뉴를 매장 범위 캐시에서 읽고 캐시 사용 중임을 표시 | stale 가격·품절 표시 정책 강화 필요 |
| 오프라인 주문 | 서비스 워커 동기화 경로는 푸드트럭용이며 일반 고객 주문 동기화 API는 없음 | 자동 재전송 금지. 일반 QR 주문은 온라인 전용이어야 함 |
| 주문 재시도 | `MenuPage`는 주문 idempotency key와 생성된 주문 참조를 유지 | 이 동작을 설치·재방문에도 유지할 회귀 테스트 필요 |
| 바로가기 | manifest shortcuts는 주문·메뉴·재고 관리자 경로 | 고객용 설치 앱 진입점 없음 |
| 알림 | Firebase 웹 푸시 코드가 있으나 고객은 주문 알림 선택 흐름이 필요 | 설치·알림 동의를 분리하고 명시적으로 요청 |

## 우선순위 실행계획

### P0 — 안전한 오프라인 및 주문 상태

1. 오프라인 시 캐시 메뉴는 읽기 전용으로 제공하고, 화면 상단에 마지막 갱신 시각과 “가격·재고가 최신이 아닐 수 있음”을 표시한다.
2. 네트워크가 없거나 API 서버가 준비되지 않은 경우 주문·분할주문·결제 요청을 막고 장바구니를 유지한다. 서버에 도달했는지 불분명한 요청은 같은 idempotency key로 결과를 조회·재시도한다.
3. 고객 주문을 IndexedDB에 넣어 복구 후 자동 제출하는 동작은 제공하지 않는다. QR 주문은 테이블·가격·재고·결제 상태가 바뀔 수 있어 조용한 재전송은 안전하지 않다.
4. 네트워크가 복구되면 메뉴를 최신화하고, 상품 가격·품절 상태가 바뀌면 장바구니에서 변경을 확인한 뒤 다시 주문하도록 한다.

**완료 기준:** 오프라인·API 503·응답 유실 시 주문이 자동 접수되었다고 안내하지 않음, 주문이 중복 생성되지 않음, 장바구니가 보존됨, 네트워크 복구 후 최신 가격·재고를 확인함.

### P1 — 고객이 원할 때 설치와 재방문

1. QR 첫 방문 직후에는 설치를 강요하지 않는다. 첫 주문 완료 또는 고객의 명시적 “홈 화면에 추가” 요청 이후에만 작고 닫을 수 있는 안내를 보여준다.
2. Android/Chromium은 `beforeinstallprompt`를 사용하고, iOS Safari는 공유 버튼 → 홈 화면에 추가 방법을 짧은 안내 시트로 제공한다. 지원하지 않는 브라우저에서는 설치 버튼을 숨긴다.
3. 고객 설치 경험의 시작 경로는 공개 매장 메뉴 또는 최근 주문으로 둔다. 고객 앱에 관리자 주문·재고 바로가기를 노출하지 않는다.
4. 설치 여부·안내 닫힘 상태는 최소한으로 보관하고, 매장 메뉴를 다시 열어도 안내가 반복되지 않도록 한다.

**완료 기준:** Android Chrome, iOS Safari, 설치된 standalone 모드에서 설치 안내가 서로 다르게 동작하고, QR 주문 첫 화면을 가리지 않으며, 관리자 전용 링크가 고객 바로가기에 나타나지 않음.

### P1 — 주문 상태 알림 선택

1. 주문 완료 후에만 “조리/준비 상태 알림 받기” 선택지를 보여준다. 메뉴 로딩 중 권한 팝업을 띄우지 않는다.
2. 푸시 수신은 알림 동의와 기기 구독 등록이 모두 완료됐을 때만 활성화하고, 거부해도 주문 화면에서 상태를 조회할 수 있게 한다.
3. 알림에는 필요한 최소 정보만 넣고, 주문 상세는 capability가 유효한 앱 경로에서 조회한다. 토큰 해제·로그아웃·계정/기기 제거 경로를 제공한다.
4. 웹 푸시가 지원되지 않거나 키/서버 설정이 없으면 SMS라고 가장하지 말고 앱 내 주문 상태 새로고침을 대체 경로로 제공한다.

**완료 기준:** 허용·거부·미지원·토큰 만료·중복 이벤트를 각각 검증하고, 알림 없이도 주문 진행 상태를 확인함. 운영 푸시는 실제 키와 서비스워커 환경 확인 전까지 “미연결” 상태로 표시.

### P2 — 오프라인 친화성과 개인정보

1. 매장·메뉴 데이터 캐시는 매장 ID로 격리하고 만료시간을 설정한다. 주문 이력·결제 정보·고객 전화번호는 서비스워커 캐시에 넣지 않는다.
2. 고객 전화번호 자동 저장은 기본 동작으로 하지 않는다. 재방문 자동 입력을 유지하려면 별도 선택 동의와 “이 기기에서 지우기” 기능이 필요하다.
3. 고객이 “최근 본 매장” 또는 즐겨찾기를 켜면 기기 내 데이터를 지우거나 초기화하는 조작을 제공한다.
4. 재연결 시에는 메뉴만 조용히 갱신하고, 재고·가격 변경은 고객에게 명확히 보여준다.

**완료 기준:** 매장 A의 캐시가 매장 B 화면에 나타나지 않고, 캐시 만료·로그아웃·사이트 데이터 삭제 뒤 민감한 고객 데이터가 남지 않음.

### P2 — 모바일 사용성·접근성

- 한 손 조작 가능한 장바구니 진입·축소, 키보드 안전 영역과 하단 고정 버튼, 큰 터치 영역을 유지한다.
- 메뉴 옵션·맵기·알레르기 정보를 메뉴를 담기 전에 읽을 수 있게 제공한다. 알레르기 정보가 입력되지 않은 경우 안전을 보장하는 것처럼 보이지 않는다.
- 음성 주문은 기본 주문 입력을 대체하지 않는 선택 기능으로 유지하고, 음성 인식 실패·권한 거부·AI 장애 시 편집 가능한 텍스트 장바구니로 돌아간다.
- 화면 낭독기 이름·포커스 이동·색상 대비·200% 글자 확대를 확인한다.

## 테스트 게이트

1. 단위: 메뉴 캐시 만료, 매장별 격리, stale 상태 표시, 설치 노출 조건, 시간 초과·재시도 키 유지.
2. 브라우저 E2E: QR → 메뉴 → 옵션 → 장바구니 → 주문 → 완료 → 재방문/주문 상태.
3. 장애 시나리오: 오프라인 주문 차단, API 503, 주문 생성 응답 유실, 결제 리다이렉트 후 복귀, 네트워크 재연결, 오래된 가격/품절.
4. 기기: Android Chrome 설치, iOS Safari 수동 설치 안내, 설치 앱의 뒤로가기·화면 복귀.
5. 개인정보: 서비스워커 캐시에서 전화번호·주문·결제 응답이 없는지 확인하고, 알림 거부 시에도 핵심 주문 확인이 가능해야 함.

## 측정 지표

- QR 진입부터 메뉴 표시까지 p50/p95 시간
- 메뉴 캐시 사용률과 캐시의 마지막 갱신 경과시간
- 주문 시도 대비 서버 확인 완료율 및 중복 주문율
- 주문 완료 후 설치 안내 노출·수락률
- 고객 알림 opt-in/거부/해제율과 알림 이벤트 지연
- 오프라인 상태에서 주문 제출이 차단된 비율 및 오인 접수율(목표 0)

## 이번 로컬 변경 범위

- 오프라인 고객 체크아웃은 주문·결제 요청을 보내지 않고 장바구니를 유지하도록 보강.
- 영업 종료 메뉴에 다음 영업 시작 시각 또는 주문 재개 안내를 표시.
- 메뉴 카드에서 매장이 등록한 알레르기 정보를 고객이 담기 전에 표시.
- PWA 전용 설치 유도·푸시 구독은 아직 구현/운영 활성화하지 않음. 매입 기능용 스키마는 별도 로컬 마이그레이션으로 준비했으며 운영 DB에는 적용하지 않음.
