## 3. 첨부용 서비스·기술 소개 초안

WeMarket는 매장의 QR·온라인 주문과 사업자 주문 관리를 제공하는 서비스입니다. 매장은 포장·배달 주문을 설정하고, 배달은 직접 수행하거나 매장과 계약한 대행사를 선택하는 방식으로 운영하려 합니다. 플랫폼 제휴를 통해 매장별 기존 대행 계약을 연결하고 접수부터 완료까지 상태를 확인하는 것이 이번 연동의 목적입니다.

- 서비스 주소: https://wemarket-saas.vercel.app
- 서버 주소: https://wemarket-eiw4.onrender.com
- 기술 환경: Node.js 서버, PostgreSQL, HTTPS API.
- 기존 준비 범위: 매장별 인증정보 암호화 저장, 배차 요청 claim 및 미확정 결과 차단, 상태 이벤트 처리·중복 방어와 후속 처리 복구.
- 추가 개발 범위: 업체별 인증, 주문 접수·취소·조회, 상태 콜백 검증·매핑, 매장 계정 연결과 샌드박스 검증.
- 요청 기능: 배달료 확인 가능 여부, 주문 접수·결과 조회·취소·배차/픽업/완료 이벤트.
- 전송 예정 항목: 주문 식별자, 출발·도착 정보, 수령자 연락처, 상품·결제 정보와 배달 요청사항. 업체 명세와 계약을 확인하여 필요한 항목만 확정합니다.
- 테스트: 합성 고객 정보·지정 시험 매장 사용. 실제 라이더 호출 및 과금 발생 여부를 확인하고 시작합니다.
- 현재 실제 대행사 API는 비활성 상태이며 제휴 승인·테스트 완료 후 단계적으로 적용할 계획입니다.

현재 서버의 콜백 경로 후보는 `/api/orders/delivery-webhooks/{provider}/{storeId}`이다. 업체의 파트너 단위 단일 콜백 요구와 인증 범위를 확인한 후 최종 URL을 등록한다. 현재 경로 그대로 수용 가능하다고 약속하지 않는다.
