# 사업자·최고관리자 API 인증정보 관리

## 사용 위치

- 사업자: 데이터 통합 센터 `/admin/stores/:storeId/integrations`의 API 인증정보 영역. 매장 소유주와 최고관리자만 조회·변경한다. 매니저·직원은 키 관리 권한이 없다.
- 최고관리자: `/admin/provider-settings`의 공통 API 설정. 서울 공공데이터·기상청 키는 모든 매장에 적용한다. 네이버 공통 기본값도 설정할 수 있다.
- WeMarket 자체 수집용 API 키는 기존 개발자 센터에서 발급한다. `integrations:write` 스코프를 화면에서 선택할 수 있다. 업체에서 발급한 키와 WeMarket 수집 키는 서로 다른 인증정보이다.

## 제공 기능

매장별 POS·외부 키오스크/테이블오더·배달·온라인 주문 업체 키와 네이버 Client ID/Secret을 등록한다. 공공데이터 키는 최고관리자 범위에만 저장할 수 있다. 목록에 키 원문을 반환하지 않으며 변경 시 입력란을 비우고 마지막 네 자리만 표시한다. 빈 필드는 기존 값을 유지한다. 새 등록에는 모든 필수 필드를 입력한다.

키 저장·활성화/중지·삭제·연결 확인을 지원한다. 서울은 쉼표로 구분한 키 최대 10개를 지원한다. 삭제하면 공통 설정 또는 기존 서버 환경변수로 돌아갈 수 있으며 화면에서 이를 안내한다. 저장된 항목을 중지하면 그 범위에서는 환경변수로 자동 우회하지 않는다.

네이버는 해당 매장 키 → 최고관리자 공통 키 → 서버 환경변수 순서로 선택한다. 서울·기상청은 최고관리자 공통 키 → 서버 환경변수 순서이다. DB에 저장된 키 변경은 다음 요청부터 사용하며 프로세스 재시작이 필요하지 않다. 공통 키 원문·마스킹 값은 사업자 화면에서 공개하지 않고 설정 여부만 보여준다.

## 연결 검증의 의미

네이버는 공식 지역검색, 서울은 LOCALDATA 첫 페이지, 기상청은 서울 관측 지점의 실제 응답 형식을 확인한다. 요청 주소는 서버가 고정하며 사용자가 임의 외부 URL을 입력할 수 없다. 오류 응답에 공급자 요청 URL·헤더·키를 포함하지 않는다.

네이버 지역검색 인증 성공은 리뷰 원문 수집을 뜻하지 않는다. 기존 공식 API가 제공하는 매장 정보·플레이스 링크 기능에 매장 키를 연결한다. 리뷰 원문은 공식 제공·계약 범위가 확보되어야 별도로 연동할 수 있다.

POS·키오스크·배달 업체의 API 규격과 연결 대상이 아직 지정되지 않았다. 키를 암호화 보관하되 연결 확인에는 `업체 어댑터 연결 필요`를 표시한다. 키 등록만으로 자동 수집 완료라고 표시하지 않는다. 실제 업체 어댑터가 연결될 때 서버 내부 resolve(provider, storeId)에서 해당 매장 키를 가져오도록 한다.

## 보안·운영

provider_credentials 테이블에 AES-256-GCM 인증 암호화로 저장한다. 암호문에 매장 범위와 공급자 이름을 결합하여 다른 매장의 암호문을 바꿔 끼울 수 없다. API에는 Cache-Control: no-store를 적용하고 인증된 소유주·최고관리자 요청만 허용한다. 브라우저 저장소에 키 원문을 기록하지 않는다.

암호화 키는 서버 `PROVIDER_SECRET_KEY`, `TOKEN_ENC_KEY`, `JWT_SECRET` 순서로 사용하고 HKDF로 용도별 분리한다. 서버 키가 없거나 너무 짧으면 평문 저장 대신 거절한다. 운영에서는 별도 PROVIDER_SECRET_KEY를 안정적으로 보관하는 것이 좋다. 이미 저장한 뒤 암호화 키를 바로 바꾸면 복호화가 실패하므로 기존 키로 복호화 후 재암호화하는 회전 절차가 필요하다. 이번 변경은 서버 암호화 키를 자동 교체하지 않는다.

서울 공급자 API의 기존 공식 주소는 HTTP와 키 경로 형식을 사용한다. 저장 암호화와 별개로 전송 보안은 공급자 주소의 한계를 따른다. 공급자가 HTTPS를 지원하는 공식 경로를 제공하면 해당 주소로 전환해야 한다.

기상청의 코드 내 고정 인증값을 제거했다. 실제 관측·이전 관측/대체값을 is_fallback/source/fetched_at으로 구분하고 관측 지점·키별로 캐시한다. 대체값은 날씨 기반 자동 가격 변경에 사용하지 않는다. 기존 고정 값이 실제 유효한 키라면 제공기관에서 폐기·재발급해야 한다.

## DB와 적용 범위

신규 마이그레이션 `20261007020000_provider_credentials`는 테이블 하나를 추가한다. 공통/매장 범위 제약·공급자 목록·매장 외래키·범위별 고유 제약을 포함한다. 기존 주문·고객·등록된 인증키를 수정하지 않는다. 이전 마이그레이션 적용 승인은 이 새 테이블의 승인을 포함하지 않으므로 운영 적용은 별도로 확인한다.

기존 웹훅 DB의 attempts와 Prisma attempt 불일치는 `@map("attempts")`로 해결했다. API 응답의 attempts 이름은 유지한다. DB 컬럼 변경은 필요하지 않으며 새 Prisma 클라이언트 생성 후 사용한다.

## 검증

SaaS 회귀 테스트는 암호화·변조 거절·사업자 격리·공통 적용·명시적 중지·네이버 우선순위·날씨 캐시와 대체값·실제 라우터의 권한 차단을 확인한다. 브라우저 테스트는 데스크톱·모바일에서 사업자/최고관리자 키 저장 후 입력란 비우기와 마스킹을 검증한다. 실제 운영 인증정보 대신 테스트용 값과 독립 PostgreSQL 스키마를 사용한다.

API 키의 실제 유효성은 사용자가 발급받은 키를 화면에 등록한 뒤 연결 확인 버튼으로 검증한다. 실제 키가 제공되지 않은 공급자는 연결 완료라고 보고하지 않는다.
