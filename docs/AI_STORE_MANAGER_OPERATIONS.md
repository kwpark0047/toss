# AI 매장 매니저 운영 구현

관리자 메뉴: `/admin/stores/:storeId/ai-manager`.

## 적용 기능

자체 주문·환불·자체 리뷰·판매 가능한 메뉴로 5분 단위 브리핑을 만든다. 같은 요일 최근 4개 구간의 완료된 시간대만 비교한다. 과거 비교 주문 30건이 부족하면 경고 수치와 원인을 만들지 않는다. 외부 통합 매출은 별도 30일 요약이며 외부 메뉴 상세 분석은 하지 않는다.

최근 28일 주문 30건, 판매 수량 5개 이상인 판매 가능 메뉴를 QR 추천 노출 대상으로 제안한다. 시간대 제안은 주문이 관측된 날 5개 이상인 시간대가 둘 이상일 때 그 중 낮은 평균 주문 시간대를 선택한다. 휴점·무주문 시간을 영업 중 유휴 시간이라고 단정하지 않는다. 매출·판매 기반 제안이며 원가 기반 수익 예측은 제공하지 않는다.

매장 소유주 또는 최고관리자가 제안을 승인한 뒤 적용한다. 매니저는 조회·대화·효과 보고만 이용한다. 제안은 생성 후 24시간까지 승인·적용할 수 있고 실행 기간은 7일이다. 한 매장에 한 실험만 동시에 진행한다. 시작·중단·승인·보류 이력을 보관한다. 반복 실행 요청은 동일 상태를 반환하고 이중 실행 기록을 만들지 않는다.

실행 결과는 고객 QR 메뉴의 `지금 추천하는 메뉴` 영역에 표시한다. 시간대 실험은 한국 시간 해당 1시간에만 노출한다. 품절·비활성·재고 0 메뉴를 제외한다. 기존 메뉴 가격·할인·정렬을 변경하지 않고 문자나 쿠폰을 발송하지 않는다. QR 메뉴 최초 로딩을 기다리게 하지 않으며 메뉴가 표시된 뒤 추천 목록을 조회한다. 목록은 1분마다 갱신되어 중단·시간대 변경이 최대 약 1분 이내 반영된다.

7일 종료 후 효과 확인 버튼으로 실행 전후 각 7일의 추천 메뉴 포함 주문 비중을 비교한다. 기간별 결제 주문 30건이 필요하다. 전체 환불·취소 주문은 제외하고 순매출은 환불을 차감한다. 메뉴 품목별 부분 환불 데이터가 없어 수량은 참고값이다. 표본 부족·중단·평가 대기를 구분한다. 대조군이 없으므로 개선 관측을 인과효과라고 표현하지 않는다. 늦은 취소·환불 반영을 위해 평가를 다시 계산할 수 있다.

## AI와 데이터 보호

문제·메뉴·시간대·지난 효과 질문에 검증된 서버 지표로 답변한다. 기존 Gemini 설정이 있으면 근거에 맞는 안내 문장을 고르는 제한된 AI 응답을 추가한다. 자유 생성된 사실·숫자·실행 명령은 사용하지 않는다. 기존 AI 서비스 사용 로그에 storeId를 기록한다. 추가 공급자 또는 요금제는 만들지 않는다.

AI 호출은 한국 날짜 기준 매장당 하루 5회로 제한한다. 실패·시간 초과도 횟수에 포함하며 매장 행 잠금으로 동시 요청 제한을 지킨다. 제한·AI 장애 시 지표 기반 답변은 제공한다. 자유 질문 원문, 전화번호, 인증키, 리뷰 본문은 AI 프롬프트에 보내지 않는다. 기능은 자유 SQL·외부 발송·무승인 가격 변경 권한을 갖지 않는다.

## DB와 배포

신규 마이그레이션 `20261007030000_ai_store_manager`는 manager_snapshots, manager_actions, manager_action_events, manager_evaluations, manager_ai_requests 다섯 테이블과 인덱스를 추가한다. 기존 주문·고객·결제 데이터는 수정하지 않는다. 매장 삭제 시 관련 기록을 삭제하고 스냅샷/실행/이벤트의 매장 참조 일치를 복합 외래키로 제약한다.

`node scripts/apply-store-manager-migration.cjs`는 운영 적용 사전 확인만 수행한다. 사용자 승인 범위에서 `--apply-approved`를 지정하여 해당 마이그레이션 하나만 트랜잭션으로 적용한다. 기존 동일 마이그레이션의 체크섬과 5개 테이블을 확인하고, 추적되지 않은 테이블이 있으면 중단한다. 다른 미적용 마이그레이션은 실행하지 않는다.

배포 순서: 회귀·독립 PostgreSQL·브라우저·보안 검증 → 승인된 운영 마이그레이션 → main 반영 → Render·Vercel 배포 → 운영 health·신규 API 인증 차단·프런트엔드 파일 확인.

스냅샷과 실행 기록 보존 정책·영업일 자정 경계 설정·외부 메뉴 매핑·정식 통제군 실험·할인/CRM 실행은 후속 확장이다. 이번 버전은 한국 표준시 달력 날짜 기준으로 분석하며 자정 이후 영업은 별도 영업일로 보정하지 않는다. AI 공급자 실제 가용성 및 인증된 화면의 키/계정 상태는 운영 로그인 후 확인해야 한다.

## 검증

- `npm run test:saas`: 한국 날짜, 비교 모수, 품절 제외, 효과 판단, 실제 라우터 권한.
- `node scripts/test-store-manager-postgres.cjs`: 독립 로컬 테스트 DB만 허용. 실제 신규 SQL·스냅샷·매장 격리·승인·동시 실행 멱등성·QR 노출·만료·성과·AI 일별 제한을 검증한다.
- `node scripts/smoke-store-manager.cjs`: 운영 API를 전부 차단한 fixture로 데스크톱 1440px·모바일 390px의 승인·실행·대화·효과 보고 및 고객 QR 추천 렌더링을 검증한다.

운영 주문량이 적은 매장은 안내만 표시되고 임의 제안을 생성하지 않는 것이 정상 동작이다.
