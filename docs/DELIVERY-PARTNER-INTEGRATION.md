# 배달대행 실 API 연동 준비

확인일: 2026-11-16. 대상: 바로고, 부릉, 생각대로. 매장별 대행사 계약을 유지한다.

제휴 창구, 공개된 발급 절차, 신청 자료와 업체별 문의 초안은 [제휴 신청 준비 자료](./DELIVERY-PARTNERSHIP-APPLICATION.md)를 참고한다. 바로고는 추가 조사에서 공개 연동 가이드와 API 규격까지 확인했다.

## 현재 확인된 상태

- `services/delivery/adapters.js`의 세 대행사는 `ready: false`이다. 바로고 공개 규격 기반 staging 코드와 콜백·재배차 검증 범위는 [구현 보고서](./BAROGO-PUBLIC-API-IMPLEMENTATION.md)에 기록했다. 운영에는 연결하지 않았다.
- 매장별 인증정보 암호화 저장과 배차 claim, 결과 미확정 처리, 중복·역순 웹훅 방어, 후속 효과 복구는 기존 배차 서비스에 있다.
- 기존 `api_key`, `api_secret` 필드는 초기 자리표시자이다. 제휴사 인증 방식이 이 두 필드라고 확정된 것은 아니다.
- `verifyHmac`의 `x-delivery-signature` 방식은 테스트 대행사 규격이다. 실제 업체의 서명 방식으로 재사용하려면 공식 규격 확인이 필요하다.

## 공식 자료 확인

| 대행사 | 확인 경로 | 다음에 필요한 자료 |
| --- | --- | --- |
| 바로고 | [고릴라 개발자 사이트 서비스 소개](https://developer.gorelas.com/introduce) | 제휴 협의 후 제공되는 연동 가이드, 선택할 API 방식, 샌드박스 계정 |
| 부릉 | [공식 홈페이지](https://vroongcorp.com/) | 계약 담당자가 제공하는 배차 API 명세와 개발 환경 접근 권한 |
| 생각대로 | [공식 프로그램 안내](https://logiall.com/index2.html) | 계약 담당자가 제공하는 배차 API 명세와 개발 환경 접근 권한 |

이번 공개 자료 조사로 부릉·생각대로의 배차 요청/취소/상태 웹훅 API 명세는 확보하지 못했다. 홈페이지나 프로그램 다운로드 주소를 API 서버 주소로 사용하지 않는다.

## 업체마다 받아야 할 연동 정보

1. 최신 명세 버전, 개발·운영 base URL, 접수·조회·취소 API 및 오류 코드.
2. 파트너 인증 방식, 토큰 발급·갱신, 매장/지점 식별자와 매장별 계약 연결 방법.
3. 배차 요청 필수 필드: 주문번호, 출발/도착 주소·좌표, 연락처, 상품, 결제·현장수금, 요청 시각과 준비 시간.
4. 중복 방지 키 지원 여부와 적용 범위, 응답 유실 시 주문번호로 결과 조회하는 방법.
5. 상태 코드와 전이 규칙, 취소 가능 시점, 취소 비용, 배달료 견적·확정 방식.
6. 웹훅 원본 예제, 인증·서명 및 재전송 검증 규칙, 이벤트 식별자 범위, ACK 형식과 재시도 정책.
7. 샌드박스 계정·테스트 매장, IP 허용 목록, 콜백 등록, 호출 제한, 운영 전환 심사 조건.

비밀키는 문서나 채팅에 기록하지 않고 매장별 인증정보 저장 기능으로 등록한다. 파트너 공통 인증과 매장 식별자가 분리된 업체는 공식 규격에 맞춰 저장 범위를 확장한다.

## 구현 및 검증 순서

1. 자료가 먼저 확보된 한 업체부터 공식 필드 매핑·인증·상태 변환을 구현한다. 나머지 업체는 비활성 상태를 유지한다.
2. 기존 `requestDispatch`의 안정적인 `idempotencyKey`를 업체 규격에 연결한다. 지원하지 않으면 미확정 요청의 조회·수동 확인 경로를 확정하고 자동 재접수하지 않는다.
3. 취소 API, 업체별 웹훅 검증·파싱, 결과 조회를 구현한다. 웹훅이 접수 응답보다 먼저 도착하는 경우와 요청 시간초과·프로세스 재시작도 검증한다.
4. 공식 예제를 이용한 계약 테스트: 성공/거절/인증 오류/시간초과/잘못된 응답, 중복·역순·위조 이벤트, 매장 간 이벤트 격리를 확인한다.
5. 대행사 샌드박스에서 접수 → 배차 → 픽업 → 완료 및 취소를 검증한다. 시험 매장과 합성 고객 정보를 사용한다.
6. 테스트·CI 통과 후 PR로 반영하고 업체 승인된 시험 매장부터 운영 검증한다. 운영 주문 발생 여부와 비용 조건을 사전에 확정한다.

바로고 공개 규격 기반 코드와 오프라인 테스트는 구현했고 실제 계정 샌드박스 검증·운영 활성화는 미완료이다. URL·필드·서명을 추측한 호출이나 실제 배차 요청은 수행하지 않았다.
