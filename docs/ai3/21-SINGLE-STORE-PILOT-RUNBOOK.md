## 향후 승인 후 활성화 순서 — 이번 작업에서는 실행하지 않음

1. **승인 및 복구점 확보.** 대상 매장 1곳, 기능, 한도, 중단 담당자와 기준을 서면 확정한다. 운영 Render·Vercel 배포 ID와 비밀을 제외한 설정 상태를 기록한다. CI·E2E 성공을 확인하고 배포·유료 시험에 대한 별도 허용을 확보한다. 승인 누락 시 여기서 중단한다.
2. **OFF 상태로 코드 준비.** 별도 승인된 배포 절차로 호환되는 서버·프론트 버전을 맞춘다. 자동 배포 차단은 유지한다. 실제 DB 스키마 변경을 이 절차에 포함하지 않는다. 기존 음성·직접 입력·장바구니·결제·사업자 승인 경로가 OFF 상태에서 동작하는지 확인한다.
3. **서버 자격·원장 준비.** 계정 모델과 공식 단가를 재확인한다. 비밀 관리 경로의 API 키, 32자 이상 ticket secret, 정확한 HTTPS Origin과 인증·TLS·영속성이 있는 전용 Redis를 확인한다. 키는 브라우저·문서·로그에 넣지 않는다. Redis 장애 시 차단을 모의 환경에서 먼저 확인한다. 기존 예산 원장을 초기화하지 않는다.
4. **단일 매장 서버 정책 검증.** 실제 정책에서 승인된 매장 하나만 `enabled=true` 후보로 설정하고 나머지는 false임을 독립 검토한다. 모델·단가·양수 예약액·월 한도·동시성·시간 제한을 확인한다. `AI_LIVE_ENABLED=true`가 필요한 단계에서도 `AI_LIVE_ALLOW_PAID=false`로 유지해 유료 진입 차단을 우선 확인한다. 정책은 서버 시작 시 로드되므로 승인된 재시작 절차로 반영한다.
5. **유료 시작 최종 승인.** 소액 실사용 검증 승인이 별도로 존재할 때만 서버 `AI_LIVE_ALLOW_PAID=true`를 반영한다. 사진·마케팅·카메라 gate는 false로 유지한다. 프론트 `VITE_AI_LIVE_UI_ENABLED`는 빌드 시 값이므로 승인된 프론트 빌드·배포가 필요하다. UI flag는 전역 노출 조건이며 매장별 보안 경계가 아니다. 비대상 매장의 서버 거부와 기존 방식 복귀를 반드시 확인한다.
6. **단계별 관찰.** 명시적 마이크 동의 후 상담 → 서버 초안 검증 → 고객 버튼 확인 → 기존 장바구니까지 합성 메뉴로 관찰한다. 실제 고객정보·카드·자동 결제는 사용하지 않는다. Manager는 읽기 전용 상담과 기존 승인 화면 이동까지만 먼저 확인한다. 실제 사업 변경 실행은 별도 승인 범위 없이는 수행하지 않는다.
7. **종료 판정.** 요청·세션 식별자, 매장, KST 월, 예약·사용량·정산, 차단·폴백 결과를 대조한다. 실제 음질·비용 검증이 미완료면 확대하지 않는다. 파일럿 종료 시 OFF로 복귀하고 아래 롤백 검증을 수행한다.

## 즉시 중단 조건과 롤백 순서

다른 매장 접근, 승인 없는 장바구니/사업 변경, 사용자 동의 없는 미디어 전송, 미확인 사용량·단가, 예산 초과 허용, Redis 장애 중 호출, 원장 불일치, 폴백 실패 또는 승인된 지출·지연 기준 위반이면 신규 요청을 중단한다.

1. 실행자가 승인된 서버 설정에서 **유료 허용과 기능 gate 및 대상 매장 enabled를 모두 false**로 복구한다. 사진·마케팅·카메라와 다른 매장이 계속 false인지 확인한다. UI만 숨기는 것으로 차단 완료를 선언하지 않는다.
2. Live 정책은 프로세스에서 보관되고 기존 연결이 남을 수 있다. 승인된 운영 중단·재시작 절차로 구 버전 인스턴스와 활성 WSS/Provider 연결을 모두 종료하고, 재시작한 인스턴스의 새 ticket·연결 거부를 확인한다. 진행 중 사진·마케팅 요청도 확인한다. 환경 변경은 이미 전송된 호출의 비용을 취소하지 않는다. 현재 저장소에 관리자용 즉시 전역 kill API가 있다고 가정하지 않는다.
3. 프론트 Live UI를 false로 빌드·반영하고 열린 탭·설치형 앱의 업데이트/새로고침 및 마이크 track 종료를 확인한다. 프론트 반영 전에도 서버 차단은 유효해야 한다. 기존 음성·직접 입력·텍스트 상담·수동 메뉴·무료 마케팅 경로로 안내한다.
4. Redis의 `spent`·`reserved`·세션·감사 기록을 보존한다. 오류 정산·끊긴 연결의 미확정 예약은 격리해 조사한다. DB/Redis 삭제, 예산 0 초기화, TTL 임의 변경, 자동 환급·재시도로 지출을 다시 허용하지 않는다. KST 월이 바뀌어도 이전 월 요청은 기존 월에 정산한다.
5. 버전 복귀가 필요하면 사전 기록한 Render·Vercel 복구점에 대해 별도 승인된 절차를 사용한다. 이 문서 작업은 배포/역배포를 실행하지 않는다. DB 역마이그레이션을 롤백에 포함하지 않는다.
6. 모든 gate false, 새 유료 요청 0, 활성 Provider 연결 0, 비대상 매장 거부, 기존 폴백·승인 경로 정상, 원장 보존을 증거로 확인한 뒤 중단 완료를 선언한다. SDK 연결/정산을 확인할 수 없으면 미확인으로 남기고 재활성화하지 않는다.
