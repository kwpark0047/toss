## 수정한 문제

1. Live가 거부하는 배열 형태의 매장 정책을 사진·마케팅이 객체처럼 인덱싱해 허용했다. 모델 단가 맵을 포함해 객체 형태를 검증하고 배열/비객체는 예약 및 Provider 호출 전에 차단하도록 맞췄다. 회귀 테스트는 수정 전에 Provider 호출이 발생하며 실패하는 것을 확인했다.
2. 공용 Redis 클라이언트에는 연결 timeout만 있고 명령 timeout이 없어, 연결된 채 응답이 멈추면 폴백도 지연됐다. `commandTimeout: 1500`을 추가했다. 운영 연결 설정을 실제 ioredis/격리 Redis에 적용해 수정 전 대기와 수정 후 차단을 재현했다. 테스트에서는 SQL 객체 접근을 금지했고 가짜 Provider만 사용했다.
3. 모바일 도구를 예산 오류 503 및 무료 초안 재진입까지 검증하도록 확장했다. 팅커벨 도구의 최초 Vite 컴파일/페이지 load 대기 시간 초과는 DOM 준비 후 실제 화면 검증을 기다리는 방식으로 조정했다. 화면·승인·폴백 assertion은 유지했다.

## 실행 경계

`127.0.0.1:16389`의 검증 전용 `--rm` Redis 컨테이너와 무작위 namespace만 사용했고 종료했다. BLPOP은 해당 테스트 연결만 지연시키며 다른 Redis 클라이언트를 전역 PAUSE하지 않았다. 앱 DB/운영 Redis·키·환경 변수·스키마는 변경하지 않았다. 외부 게시·운영 배포·실제 고객정보·카드 청구·유료 API 호출은 없었다.

명령 timeout은 Redis 서버에서 이미 실행됐을 수 있는 예약을 취소·환급한다는 뜻이 아니다. 불확실한 예약을 임의 환급하거나 유료 호출을 재시도하지 않는 보수적 정책을 유지한다. 이번 검증은 연결 장애·지연/복구 정산을 다루며, 운영 Redis의 영구 데이터 유실 복구나 실청구액 검증은 포함하지 않는다.
