# 바로고 옵션·예약 주문: 계정 발급 전 구현

2026-11-17. 운영 배차와 고객 예약 접수는 비활성이다. 이번 범위는 코드·오프라인 검사·PR이며 운영 DB 적용·머지·배포는 포함하지 않는다.

## 옵션 상품

서버 주문 가격 계산기가 저장한 `price`는 옵션이 포함된 한 개당 가격이다. 저장된 canonical 옵션의 `priceAdjustment` 합계를 차감하여 원래 단가를 복원한다. 현재 canonical 옵션에는 별도 수량이 없으므로 선택마다 수량 1로 매핑한다. 부모 상품 수량을 옵션에 다시 넣지 않는다.

예: 옵션 포함 단가 14,000원, 옵션 추가금 2,000원, 상품 수량 2개라면 기본 단가는 12,000원이다. 전송 합계는 `(12,000 + 2,000 × 1) × 2 = 28,000원`이다. 배달팁은 별도 DELIVERY_TIP 상품으로 유지한다. 할인은 기존 주문의 할인 후 총액과 DONE 결제 합계에 반영한다.

무료·음수 조정 옵션을 정수 금액 그대로 보존하며, 기본 단가 또는 최종 단위 합계가 음수이면 거절한다. 옵션 이름·수량·정수 범위·합계·중간 계산 오버플로와 손상된 저장 JSON을 검사한다. client API의 옵션 수량은 부모 한 개당 수량이다. canonical 저장소가 지원하지 않는 별도 옵션 수량을 임의 해석하지 않는다. 실제 업체의 음수 옵션 수용 정책은 계정 발급 후 샌드박스에서 확인해야 한다.

## 예약 스냅샷

명시적인 `delivery_reservation` 객체를 사용한다.

```json
{
  "dropWishAt": 1800172800000,
  "pickupWishAt": 1800171000000,
  "reservedOrderDisplayTime": 60
}
```

시각은 epoch 밀리초이며 문자열 날짜를 추측해 변환하지 않는다. 요청·저장·배차 사전검증·클라이언트 전송에서 같은 규칙을 쓴다.

- 예약 도착 희망 시각: 검증 시각으로부터 90분 이상, 두 달 이내.
- 라이더 노출: 정수 20~90분.
- 픽업: 도착 시각에서 노출 시간을 뺀 시각 이상, 도착 20분 전 이하이며 과거 불가.
- 예약 픽업에는 일반 즉시 주문의 '현재로부터 90분 이내' 제한을 적용하지 않는다.
- 예약 필수값 누락·미지원 필드·즉시 주문에 끼워 넣은 예약 필드는 거절한다.
- 두 달은 서비스의 KST 달력 기준으로 계산하고 말일·윤년을 보정한다. 공개 문서의 '2개월' 표현에 대한 서비스 구현 기준이며 실제 업체의 경계 해석은 샌드박스에서 확정한다.

배차 시에도 원래 저장한 시각을 재검증한다. 유효기간이 지난 예약을 현재 시각 기준으로 다시 잡거나 자동 재접수하지 않는다. 자동 실행 스케줄러는 추가하지 않았다.

## 비활성 경계

기본 `OrderService`는 예약 배달 주문을 409로 거절한다. 준비 경로는 생성자 의존성 주입인 `deliveryReservationsEnabled:true`로만 테스트한다. HTTP 본문이나 환경변수로 열 수 없다. 고객 예약 UI도 추가하지 않았다. 기존 즉시·포장·매장식사 주문은 유지한다.

운영 등록 바로고·부릉·생각대로 어댑터는 계속 `ready:false`이다. 예약은 명시적으로 주입한 staging 어댑터에서만 오프라인 검증한다. 업체 호출·실배차·과금은 수행하지 않는다.

## 스키마

`20261117010000_barogo_reservation_snapshot`는 orders에 nullable JSONB `delivery_reservation` 열 하나만 추가한다. 기존 주문은 NULL로 남으며 보정·삭제하지 않는다. **운영 미적용이며, 향후 배포 전 별도 승인을 받아 적용해야 한다.** 운영 마이그레이션/배포 게이트는 이번 작업에서 변경하지 않는다.

## 검증 범위

공식 옵션 예제의 수량·총액 관계, 저장된 옵션의 기본 단가 복원, 무료/음수 옵션, 잘못된 타입·금액·수량·이름·오버플로, 예약 하한·상한·픽업 구간·말일·윤년, 늦은 배차 시 재검증과 기본 고객 경로 차단을 검사한다.

격리된 로컬 PostgreSQL에서는 실제 추가 SQL과 옵션·예약 스냅샷의 저장→조회→staging HTTP 요청 변환을 검사한다. 운영 레지스트리가 비활성인지도 같은 테스트에서 확인한다. 실제 업체 샌드박스 검수는 계정 발급 후 수행한다.
